digiemu 0.3.0 adds **MIDI** to both products and supports **Digitone OS 1.44**, which failed to set up in 0.2.0. It also adds **Check firmware...**, which checks a custom firmware build before it goes on a device.

## Get started

1. Download **digiemu-win64-0.3.0.zip** below and unzip it anywhere you can write to, except a OneDrive folder.
2. Get the firmware from Elektron's website: `Digitakt_OS1.53.syx` for the Digitakt, or `Digitone_and_Digitone_Keys_OS1.44.syx` (or 1.43) for the Digitone.
3. Run `digiemu.exe`, click **Add firmware** and pick the `.syx`. Setup runs once per firmware and takes about 25 seconds on a desktop.
4. Click **Play**.

The exe is not code-signed, so Windows SmartScreen asks first: choose *More info*, then *Run anyway*. A PC with Smart App Control turned on blocks it. Tested on Windows 11, 64-bit.

**Upgrading from 0.2.0:** unzip 0.3.0 into a new folder, then move the `firmware` folder from your 0.2.0 folder into it. A Digitakt or Digitone set up with 0.2.0 opens where you left off, without being set up again. If a Digitone OS 1.44 setup failed under 0.2.0, select it and click **Reset to factory**: its saved boot was made without the Digitone's second processor.

## What's new

- **MIDI in and out on the DIN ports**, on the Digitakt and the Digitone.
  - The new MIDI button picks a device to play from and one to send to, and remembers them for each firmware.
  - The firmware's own MIDI CONFIG still applies. After setup, PORT CONFIG > INPUT FROM is USB only, so set it to MIDI (and OUTPUT TO, for MIDI out).
  - It follows an external MIDI clock, smoothed so that the tempo holds steady.
  - Windows has no virtual MIDI ports. To connect a DAW, make a loopback port (with loopMIDI, for example) and pick it in the MIDI window.
  - Thanks to @amorgan101010, who wrote MIDI in and out.
- **Digitone OS 1.44.** Its setup stopped with "settle: not settled after 3000M instructions", because the Digitone's second processor never started. It now sets up in under a minute and plays, and its key LEDs light.
- **Check firmware...** checks a custom firmware build before you flash it, against the stock firmware you have set up. It runs the build's own bootstrap and boots it under a stricter emulator. It compares every screen and sample with stock's, and can also time the audio render against its deadline. It ends with PASS or FAIL and the reasons. From the command line it is `digiemu-console.exe --check FILE.syx [--baseline STOCK.syx] [--timing]`.
- **Saved sessions reopen after long play.** In 0.2.0, a session closed after about a minute of play could not be opened again, and the app dropped it.
- **The panel.**
  - The layout follows the hardware's more closely.
  - Master Volume (top left) turns with the mouse wheel or a drag.
  - A screen no longer keeps leftovers of the one before it.
  - Thanks to @GnarlyAsparagus7, who reworked the layout and added Master Volume. They also added live audio on macOS, which is for running from source.
- **The emulated memory is 128 MB**, as on the hardware, not 64 MB. This matters most to Check firmware..., which no longer fails a build that loads more than about 4 MB of samples.

## Known limits

- **MIDI:**
  - a buffer the firmware sends by DMA goes out at once, not at 31250 baud;
  - there is no USB MIDI;
  - OUT PORT FUNC's DIN 24 and DIN 48 sync modes are not modelled;
  - on Windows, MIDI data passing through a device has not been tested yet. The ports were listed, chosen and remembered there, and MIDI in and out were tested on Linux.
- **Tested releases** are Digitakt OS 1.53 and Digitone OS 1.43 and 1.44. Digitakt OS 1.54 sets up and boots once you confirm, but has not been tested further. Other releases of the two also run once you confirm; other Elektron products are recognised and turned away.
- The Digitone runs as a plain Digitone. The Digitone Keys' keyboard, wheels and extra keys are not there.
- The Digitakt's factory *sample* library lives on the real device's storage, not in the firmware, so `/factory` is empty.
- Whether 44.1 kHz samples play at the right pitch is not verified yet.
- Control Flow Guard is cleared in both exes, because Unicorn's `longjmp` fails under it. The process then has the same protections as `python.exe`.
